# Инфраструктура MVP на арендованных серверах (23.08.2026)

Принцип: CPU-часть (media + backend) — арендованный bare-metal/VPS рядом с выбранным GPU-регионом; AI-часть — RunPod; клиенты — мобильные приложения. Цены — порядок величин, проверять на момент закупки.

## 1. Железо (аренда)

| Машина | Роль | Спека | Где | ~Цена |
|---|---|---|---|---|
| Media-сервер | WebRTC SFU (LiveKit), TURN (coturn), сигналинг | 8–16 ядер, 32–64 GB RAM, 1 Gbps, публичный IPv4, низкий пинг до GPU-региона | Hetzner Falkenstein/Frankfurt (если RunPod EU) | €50–120/мес |
| Backend | API: auth, контакты, профили, push, биллинг, Postgres+Redis | 4–8 vCPU, 16 GB | тот же ДЦ (или та же машина на MVP) | €20–50/мес |
| GPU | STT + перевод + TTS | L4 / RTX 4090 / L40S; MVP — 1 GPU тянет несколько параллельных звонков | RunPod (EU-регион, ближайший к media) | warm 24/7 ≈ $300–700/мес; serverless — по минутам |

Ключевое: замерить пинг media↔GPU; цель 2–10 ms (тот же metro). Free-тариф позже — serverless scale-to-zero, Paid — warm workers.

## 2. Софт по слоям

- **Клиенты:** iOS + Android (React Native/Flutter или нативно), LiveKit client SDK.
  - iOS: CallKit + PushKit (VoIP push) — иначе входящий звонок не разбудит убитое приложение.
  - Android: FCM high-priority + ConnectionService/Telecom API.
- **Media:** LiveKit OSS (SFU + **LiveKit Agents** — фреймворк ровно под голосовые AI-пайплайны), coturn (TURN/STUN).
- **AI-пайплайн (на GPU):**
  - VAD/turn detection: Silero VAD.
  - Streaming STT: faster-whisper (large-v3) / streaming-обвязка; иврит — модели ivrit.ai; на старте можно API (Deepgram/Ivrit).
  - Перевод: на старте LLM API (Claude/GPT, streaming); потом локальная модель на том же GPU.
  - Streaming TTS: XTTS-v2 / Kokoro / Piper; на старте можно Cartesia/ElevenLabs API. Клонирование голоса — не в MVP.
  - Orchestrator: Python-сервис (LiveKit Agents): семантический чанкер, отмена TTS при перебивании, language handshake (Direct/Translated).
- **Данные:** PostgreSQL, Redis (presence, сессии, потом matching-пул), S3-совместимое хранилище (Hetzner Object Storage / Backblaze) для аватаров и голосовых.
- **Observability:** Prometheus + Grafana + Loki, Sentry. Метрики задержки по этапам пайплайна — с первого дня (это главный KPI продукта).
- **Деплой:** Docker Compose на MVP (без Kubernetes), Caddy/Traefik для TLS.

## 3. Внешние сервисы (без них никак)

- SMS-верификация номера: Twilio Verify / Vonage / Plivo (~$0.01–0.05 за SMS).
- Push: APNs + FCM (бесплатно).
- Apple Developer $99/год, Google Play $25 однократно.
- Домен + почта. TLS — Let's Encrypt.
- Платежи (когда появится Paid): App Store/Play billing (комиссия 15–30%) или Paddle/Stripe для веба.

## 4. Смета MVP

| Этап | Состав | ~В месяц |
|---|---|---|
| Разработка/демо | 1 сервер Hetzner + RunPod по часам + API (STT/TTS/LLM) | $150–400 |
| Пилот (десятки пользователей) | media+backend + 1 warm GPU + API-остатки | $500–900 |
| Ранний рост | 2 медиа-региона + 2–3 warm GPU + serverless overflow | $1.5–3k |

Переменная себестоимость переведённой минуты на self-hosted: ориентир $0.01–0.05 (падает с батчингом); на чистых API — $0.05–0.15. Direct-звонки — копейки (только трафик TURN).

## 5. Режим разработки: соло-основатель + Claude (принято 23.08.2026)

Разработка — основатель с Claude Code; тестеры — основатель + ивритоговорящий; расходы — только серверы и GPU-минуты во время тестовых сессий.

**Этап 0 — $0, локально на Mac.** Весь пайплайн собирается и отлаживается локально: LiveKit dev-server в Docker, whisper.cpp/faster-whisper на CPU/MPS, локальный TTS. Медленно, но механика (VAD, чанкер, перебивания, handshake) отлаживается бесплатно. Клиент — **веб** (браузер, LiveKit web SDK): никаких сторов, тестер открывает ссылку; iOS Safari поддерживает WebRTC. Натив и Apple Developer ($99/год) — потом.

**Этап 1 — реальные тесты RU↔HE:**
- VPS Hetzner (CX32/CCX23) под LiveKit+coturn+backend: **€10–30/мес**.
- RunPod GPU (L4/4090) **только на время сессий**: pod стартует перед тестом, гасится после; биллинг посекундный. ~$0.35–0.70/час.
- RunPod network volume 50–100 GB (модели не перекачивать): **~$4–7/мес**.
- 40 часов тестов/мес → GPU ≈ $15–30.

**Итого этап 1: ~$40–80/мес.** Разовые: домен ~$10/год. SMS-верификация в dev не нужна (тестовые аккаунты с фиксированным кодом).

Перевод — self-hosted на том же GPU (24 GB хватает: Whisper large-v3 ≈ 4–5 GB + XTTS ≈ 4 GB + квантованная LLM 7–12B ≈ 6–10 GB), чтобы не платить за LLM API.

## 6. Этапность (важно)

1. **Неделя 1–3:** пайплайн на managed API (Deepgram + LLM API + ElevenLabs/Cartesia) поверх LiveKit — доказать UX RU↔HE, ничего не хостить кроме media.
2. **Дальше:** переносить слои на RunPod по одному (сначала STT, потом TTS, потом перевод) — ради маржи и задержки.
3. **Потом:** co-location media↔GPU, региональные пулы, serverless для Free.

Не строить self-hosted всё сразу: магию доказывают на API за недели, экономику чинят потом.

## 7. Сверка сметы со скелетом Этапа 0 (дополнение, 23.08.2026)

Раздел дописан после того, как архитектура скелета была зафиксирована в [03-architecture.md](03-architecture.md). Разделы 1–6 выше не менялись — это оценки до реализации; здесь то, во что они превратились.

**Что подтвердилось.** «Этап 0 — $0, локально на Mac» оказался верен и даже строже: скелет запускается вообще без ключей и без Docker, потому что `mock`-провайдеры — значение по умолчанию для всех трёх стадий. Расход на этапе отладки механики — ноль.

**Что изменилось.**

| Пункт раздела 5 | Как в скелете |
|---|---|
| «LiveKit dev-server в Docker» | Docker не нужен: `livekit-server` 1.13.5 из Homebrew, свой `livekit.yaml`. Запуск с `--dev` **запрещён** — он слушает только loopback и использует другой UDP-порт |
| «whisper.cpp / faster-whisper на CPU/MPS локально» | На 8 GB M1 не делаем: память общая с SFU, бэкендом и браузером. Локальная стадия — не маленькая модель, а детерминированный `mock`, у которого другая задача (механика, а не качество) |
| «локальный TTS» | То же: `mock`-TTS синтезирует речеподобный тон в реальном времени, чтобы отлаживать отмену и barge-in |
| «RunPod GPU только на время сессий, ~$0.35–0.70/ч» | Отложено. Пока дешевле и быстрее облачные API; точка безубыточности self-hosted STT — примерно 4 одновременных потока ([05-providers.md](05-providers.md), §8) |
| «Перевод — self-hosted, чтобы не платить за LLM API» | Наоборот: LLM-перевод оказался **обязательным**, а не дорогой заменой NMT. Только ему можно сообщить пол говорящего, пол слушающего и регистр ты/вы, без которых грамотный иврит недостижим. И он вышел дешевле посимвольных MT-API — $0.0029 против $0.0164 за минуту |
| «XTTS-v2 / Kokoro / Piper» как варианты TTS | Для иврита неверно: **ни у одного из них иврита нет**. Строку считать исправленной здесь |

**Реальные расходы Этапа 0.**

| Режим | Что включено | Стоимость |
|---|---|---|
| Mock (по умолчанию) | всё локально, ключей нет | **$0** |
| Реальные провайдеры | Deepgram Nova-3 + Gemini 3.5 Flash-Lite + Cartesia Sonic 3.5 | **≈ $1.0–2.8 за час** двустороннего разговора |
| Реальные, экономный набор | тот же STT/MT + Google Chirp 3 HD (1M символов/мес бесплатно ≈ 18 ч синтеза) | **≈ $0.75 за час**, первые ~18 ч синтеза в месяц — даром |
| Удалённый тестер | LiveKit Cloud, бесплатный tier «Build» (5 соединений, 5 000 мин/мес) | **$0** |

40 часов тестов в месяц на экономном наборе ≈ **$30/мес** — тот же порядок, что итог «этап 1: ~$40–80/мес» выше, но без аренды VPS и GPU. VPS и RunPod из разделов 1 и 5 сдвигаются на момент, когда появится больше двух тестеров или потребуется постоянно доступный адрес.

**Что из раздела 1 сдвинулось вправо.** Hetzner-машины под media и backend не нужны, пока тестеров двое: их роль на Этапе 0 играет Mac плюс, при необходимости, LiveKit Cloud. Разбор по стадиям — [05-providers.md](05-providers.md), операционная часть — [04-runbook.md](04-runbook.md).

## 8. Решение по серверам на этап двух тестеров (дополнение, 23.08.2026)

Раздел дописан перед первой сессией с живой второй тестировщицей на второй машине в другой сети. Разделы 1–7 не менялись. Решение короткое: **арендуется ноль машин, включая ноль GPU.** Ниже — почему, сколько это стоит на самом деле и по каким признакам решение перестанет быть верным.

### 8.1 Почему не арендуется GPU

Обычный аргумент за GPU — «перенесём стадии к себе и перестанем платить за API». Здесь он не работает, и не по экономическим причинам.

**Ивритский TTS нельзя self-host'ить вообще.** Не «дорого» и не «хуже» — не существует открытой модели, которую можно поставить на арендованную карту и получить ивритскую речь на приемлемых условиях. Разбор в [05-providers.md](05-providers.md), §5: у XTTS-v2, Piper, Kokoro, Rime и Hume иврита нет; у `facebook/mms-tts-heb`, MamreTTS (веса) и `phonikud-tts-checkpoints` — некоммерческие лицензии; Chatterbox Multilingual иврит умеет, но у него **нет streaming** и в каждый выход вшит водяной знак. Значит, **самая чувствительная к задержке стадия остаётся вендорским вызовом при любом раскладе**. А раз TTS всё равно уходит в облако, аренда карты ради двух оставшихся стадий отбивает только их долю — а это ~29% счёта (§6.1 в [05-providers.md](05-providers.md): TTS ≈ 71%).

**Двое тестеров — это один одновременный звонок.** Точка безубыточности self-hosted STT — примерно 4 одновременных потока ([05-providers.md](05-providers.md), §8), и это ещё при условии, что та же карта тянет TTS и MT. При одном звонке API и дешевле, и быстрее в разработке, без всяких оговорок.

**Аренда за границей транспорт ухудшает.** У Hetzner нет израильской локации: TCP connect с этого Mac до Falkenstein — 75 мс против **20 мс** до нашего edge LiveKit Cloud, который стоит в Иерусалиме ([04-runbook.md](04-runbook.md), §9.4). Европейский VPS не приблизил бы агента к SFU, а отодвинул бы его на 55 мс.

### 8.2 Почему не арендуется даже VPS

Честная причина — не цена. Hetzner CX22 стоит €4.49/мес, это не аргумент. Аргумент в том, что VPS приносит с собой работу, которую иначе делать не надо: провижининг, Caddy и TLS под backend и web, открытие UDP 50000–60000 и — то, о чём обычно забывают — **настройка TURN-over-TLS с настоящим сертификатом**. У голого `livekit-server` нет запасного пути на 443, а домашняя сеть второй тестировщицы — ровно то место, где блокировка UDP и случается. LiveKit Cloud этот резерв даёт из коробки.

**Исправление от 24.08.2026.** Предыдущая редакция утверждала здесь, что SFU стоит в Европе и что co-location агента с ним сэкономит ≈180 мс, рекомендуя деплой агента в регион `eu-central`. Это неверно: edge LiveKit Cloud нашего проекта резолвится в Oracle Cloud **Иерусалим**, 20 мс от Тель-Авива, и агент уже находится рядом с ним. Рекомендация переселить его в Европу **добавила бы** около 120 мс.

Что VPS действительно покупает — не задержку, а безотказность: сейчас бэкенд, агент и туннель живут на ноутбуке и умирают вместе с ним. Плюс постоянный адрес вместо одноразового имени туннеля, которое при каждом перезапуске обнуляет отправленную ссылку и разрешение на микрофон. Разбор и выбор провайдера — [../eval/server-placement.md](../eval/server-placement.md).

### 8.3 Что реально тратится

| Статья | Как | В месяц |
|---|---|---|
| Транспорт (LiveKit Cloud, tier «Build») | 5 000 participant-минут ≈ 27,7 ч переведённых звонков, 50 GB, карта не нужна | **$0** |
| Публичный HTTPS-адрес (Cloudflare quick tunnel) | без аккаунта, без лимита трафика | **$0** |
| Хостинг backend / agent / web | Mac основателя | **$0** |
| Mock-режим целиком | без ключей | **$0** |
| Реальные провайдеры | ≈ $2.61 за час двустороннего разговора, из них 71% — TTS | по факту |
| Cartesia Pro | 100 000 кредитов ≈ 2,7 разговорного часа | **$5** |

Реалистичный тестовый месяц — шесть часовых звонков с реальными провайдерами — **≈ $16 всего**, включая подписку Cartesia. Фиксированных обязательств нет: в mock-режиме месяц стоит ноль.

Поправка к таблице в §7 выше: там бесплатный tier LiveKit Cloud описан как «5 соединений». **Это неверно** — одновременных участников там 100, а пятёрка относится к отдельному счётчику agent-сессий. Правильные цифры — [04-runbook.md](04-runbook.md), §9.3.

Ограничитель на этом этапе — **не деньги, а кредиты Cartesia**: бесплатных 20 000 хватает примерно на 27 минут синтеза, то есть на половину одного часового двустороннего звонка.

### 8.4 Когда это решение станет неверным

Условия сформулированы так, чтобы их можно было проверить, а не почувствовать.

**Арендовать VPS, когда наступит любое из:**

1. **Нужен постоянный адрес.** Имя quick tunnel случайно и умирает с процессом: каждая сессия — новая ссылка и повторный запрос микрофона у тестера. Как только тестеров становится больше двух или сессии становятся регулярными, это перестаёт быть мелкой платой.
2. **Замеренная сквозная задержка не влезает в коридор.** Если `speech_start_to_first_audio_ms` (p90) на реальных провайдерах стабильно выше 2,5 с и вычитание ~180 мс транспорта картину не спасает — агента пора двигать к SFU. Сначала попробовать бесплатный вариант: agent-регион LiveKit Cloud. VPS — только если этого мало.
3. **Кончаются participant-минуты Cloud.** 5 000/мес ≈ 27,7 ч переведённых звонков. Раньше упрётся Cartesia, но если нет — считать это сигналом.
4. **Появляется что-то, что должно жить между сессиями** — Postgres вместо хранилища в памяти, накопление eval-логов вне ноутбука, доступ к отчётам не с Mac основателя.

Порядок при этом: сначала LiveKit Cloud остаётся SFU, а VPS берёт на себя backend + agent. Самостоятельный `livekit-server` заводить последним — вместе с ним приезжает TURN-over-TLS, которого раньше не было.

**Арендовать GPU, когда наступит и первое, и второе:**

1. **Четыре или больше одновременных потоков STT** (то есть два и больше одновременных переведённых звонка) — это точка безубыточности L4 против облачного STT.
2. **И появится путь для ивритского TTS**: либо коммерчески лицензированная streaming-модель с ивритом, которой сегодня нет, либо осознанное согласие оставить TTS вендорским навсегда. Без второго пункта GPU отбивает только STT и MT, то есть меньше трети счёта, и сам себя не окупает.

Пока верно только первое — правильный ход не GPU, а более дешёвый STT-вендор: Soniox даёт $0.12 за поток-час против $0.58/час у Deepgram на двух потоках, и при этом лучше на иврите.

Кандидаты моделей, размеры карт и замеры на будущее — [05-providers.md](05-providers.md), §8. Здесь только решение: **сегодня — ничего не арендуем.**
