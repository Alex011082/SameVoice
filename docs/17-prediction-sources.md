# Источники кандидатов: ветка памяти с приоритетом + сохранение стиля

Решения основателя 31.08.2026, сформулированы после экспериментов 6–7
([../eval/gpu-cost/RESULT.md](../eval/gpu-cost/RESULT.md)). Числа ниже — из
офлайн-симуляции схемы на артефактах эксп. 7 (без нового железа).

## 1. Схема: на первых звуках слова стартуют три ветки

1. **Ветка памяти** — лезет в память пары (прошлые разговоры, привычные
   обороты юзера) и достаёт кандидатов. **Имеет приоритет**: её кандидаты
   встают в начало общего списка.
2. **Две ветки предсказания** — LM-кандидаты (сегодня это один вызов
   предиктора: ширина списка бесплатна, эксп. 2; «две ветки» вырождаются в
   один Top-K, и это дешевле, чем два вызова).
3. **Арбитр — акустика** (7–13 мс на проверку, эксп. 1): судит кандидатов
   всех веток по первым 50–250 мс слова.
4. **Если звук подтверждает кандидата памяти — LM-ветки гасятся.** В числах:
   проверка памяти стоит ~7 мс, вызов LM — 57–337 мс. Подтверждённая память
   позволяет вообще не платить за LM на этом слове. Сегодня таких слов было
   бы 4 из 32 (12.5%); доля растёт с объёмом памяти.
5. Когда память подтверждается часто, она получает больше бюджета: глубже
   ретрив, длиннее окно, обороты юзера. Когда промахивается — сжимается.

### Что показала симуляция (на данных эксп. 7)

| подход | recall@20 | ловит слова из памяти | цена |
|---|---|---|---|
| LM + контекст (E) | 28.1% | 0 из 4 | 337 мс |
| память В ПРОМПТЕ LM (F) | 34.4% | 2 из 4 | >337 мс (промпт длиннее) |
| **слияние с приоритетом памяти** | 34.4% | **4 из 4** | **как E: промпт не растёт, ретрив ~0 GPU** |

Слияние ловит ВСЕ слова, звучавшие в прошлых разговорах (промпт-подход — половину),
и не удлиняет вызов LM. Схема основателя выигрывает у промпт-инъекции по обеим осям.

Найденный при симуляции регулятор: **сколько кандидатов память смеет вставить**.
Без ограничения она вытесняет LM-попадания из двадцатки (28.1%), при потолке 8 —
34.4%. Внутри ветки памяти нужен свой ранжировщик (по релевантности теме и
свежести), тогда потолок можно опустить до 3–5 и суммарный recall вырастет —
это следующий замер.

Урок из той же симуляции: **числительные в памяти нормализовать обязательно** —
STT пишет «12», человек говорит «двенадцатое»; без раскрытия цифр память слепа
к самым дорогим словам (даты, суммы).

## 2. Стиль: переводим язык, не социальный слой

Продолжение принципа идентичности («переводим язык, не личность»):
**сохраняется и регистр речи**. Человек, говорящий просто, в переводе не
должен звучать как чиновник; образованная речь не упрощается. Уровень языка —
измеримое свойство (частотность лексики, длина фраз, доля разговорных форм) —
**не реализовано, не измерено**; пока фиксируется как требование к MT-стадии.

Практическое следствие: стилевое условие умеет нести только LLM-перевод
(Gemini — строчка в промпте). Marian стиль не примет — ещё один аргумент в
паре «скорость Marian против управляемости LLM» (docs/09).

### Платный выбор стиля

По умолчанию — твой собственный регистр, всегда. **На платных тарифах** юзер
может выбрать стиль на конкретный звонок: например, «официальный» для звонка
в банк или госучреждение. Это его слова, его голос, его выбор — продукт лишь
«одевает» речь по случаю. Выбор на звонок, не навсегда; вернулся в обычный
разговор — вернулся твой регистр.

## 3. Память с контекстом сущностей + звуковое сито (решение 31.08, вечер)

**Схема хранения**: память держит не голые слова, а записи с контекстом:

```
слово: Амин
роль: коллега по работе
связь: часто фигурирует в разговорах с абонентом N
частота / свежесть: 14 упоминаний, последнее — вчера
```

Ретрив ветки памяти фильтруется дважды: (1) контекст звонка — кто на линии,
тема (запись «Амин» почти не весит в звонке жене, много весит в звонке N);
(2) **звуковое сито** — CTC-фрагмент первых миллисекунд слова сужает область
поиска до слов, начинающихся похоже.

**Симуляция сита на артефактах эксп. 5 (реальный голос основателя, словарь
памяти пары — 183 слова):**

| окно | улика есть | истина прошла бы сито | сжатие словаря |
|---|---|---|---|
| 50 мс | 6/32 | 0 | 183→35 |
| 150 мс | 14/32 | 3/14 | 183→16 |
| 250 мс | 27/32 | 9/27 | 183→12 |

Сжатие работает (×5–18). Но **жёсткое сито сегодня выбрасывает правильное
слово в двух третях случаев** — улика шумная: онсеты размечены Whisper
предварительно (протокол корпуса это предсказывал), CTC на 50–150 мс почти
пуст. Следствия:

1. Сито включается только **мягким** (перевзвешивание, не отсев) — тот же
   принцип, что у пруннера: «понизить, а не удалить» (docs/11).
2. Качество улики упирается в разметку онсетов → **форс-алайнмент корпуса
   (MFA / CTC-выравнивание) поднимается в приоритете**: он бесплатный,
   локальный, и разблокирует сразу и сито, и честные окна пруннера.
3. Сито само по себе стоит ~0 GPU — дорогая часть была и остаётся качеством
   улики, а не поиском по памяти.

## 4. Выход схемы: выжившие взвешиваются, не убиваются (решение 31.08, ночь)

Именование фиксируется по основателю: **три ветки — Память + две Генерации
разных направлений**. Направления генерации определены содержательно, по
измеренным слепым зонам LM (эксп. 5б):

- **Г1 — разговорное продолжение**: LM + контекст (нынешний предиктор);
- **Г2 — слотовая ветка**: если позиция пахнет слотом (дата, сумма, имя,
  день недели), кандидатов поставляет генератор слота, а не LM — ровно те
  классы, где LM промахнулся во всех trap-строках корпуса.

**Принято**: после арбитра выжившие кандидаты всех веток не удаляются —
взвешиваются и выдаются (принцип пруннера «понизить, не удалить» действует
на всю схему). «Гашение LM» — про экономию невызванного вызова, а не про
удаление уже полученных кандидатов.

**Поправка к «по одному месту с каждой ветки», измеренная симуляцией**
(артефакты эксп. 7, топ-3):

| правило выхода | recall@3 |
|---|---|
| топ-3 только LM | 15.6% |
| тройка с КВОТОЙ: 1 место памяти + 2 LM | 6.2% |

Гарантированная квота места по происхождению **вредит**: пока ветка памяти
слаба (28 строк из 32 — без следа в памяти), её зарезервированное место
отбирает у сильной ветки третий шанс. Симуляция при этом не включает
арбитра (улика пока шумная) — то есть квота наказана даже в лучших для неё
условиях.

**Решение: места в тройке — по весу, не по квоте.**
`вес = приор ветки × акустическая оценка`. Приоритет памяти реализуется
весом: при акустическом подтверждении её кандидат взлетает на первое место
(эксп. 7: слово из памяти — ранг 1), при шуме — не занимает место даром.
Разнообразие обеспечивается на ВХОДЕ (три ветки поставляют кандидатов из
разных миров), а не квотами на выходе.
