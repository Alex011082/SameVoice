# Субтитры в живом звонке — правила и решения

Повод: обсуждение Subtitle Edit (23.08.2026). Ниже — что из мира субтитрования применимо к SpeakEasy, а что нет.

## Subtitle Edit: что это и наша польза

Открытый десктопный редактор субтитров (автор Nikolaj Olsson, .NET, в основном Windows). Умеет: синхронизацию по волновой форме/спектрограмме, конвертацию сотен форматов, OCR картиночных субтитров, «fix common errors», интеграцию с Whisper для транскрипции и с движками перевода, поддержку RTL для иврита/арабского.

**Как компонент продукта — не подходит.** Это офлайн-инструмент над файлами (SRT/ASS и т.п.), а у нас поток аудио и субтитры, которые появляются во время речи. Ничего из его кода в real-time путь не встаёт.

**Где реально пригодится — офлайн, на нашей стороне:**
1. **Сборка тестового корпуса RU↔HE.** Записываем тестовые звонки → прогоняем через Whisper → правим и выравниваем в редакторе субтитров → получаем эталонный набор, на котором меряем WER для STT и качество перевода при смене провайдера/модели. Без такого корпуса «стало лучше или хуже» — вкусовщина.
2. **Библиотека правил читаемости** (см. ниже) — накопленный опыт субтитрования, который мы копируем в UI.

Оговорка: Subtitle Edit — Windows-приложение; на Mac потребуется VM/wine либо альтернатива (Aegisub, либо просто Whisper + ручная правка). Для нашей задачи корпус можно вести и в обычном текстовом формате.

## Ключевое отличие: подготовленные субтитры ≠ живые

| | Подготовленные (кино) | Живые (наш звонок) |
|---|---|---|
| Текст известен заранее | да | нет, растёт по мере речи |
| Можно перекомпоновать | да | нет |
| Главный враг | читаемость | **мерцание/переписывание** |
| Задержка | нулевая | 0.5–2 с |

Главная ловушка живых субтитров: STT отдаёт частичные гипотезы, они переписываются на лету («я завтра» → «я завтрак» → «я завтра к»). Глазу это невыносимо — хуже, чем задержка.

**Решение: политика стабильности.** На экран выводим только то, что перестало меняться (local agreement: слово печатаем, когда две последовательные гипотезы его подтвердили), «хвост» показываем приглушённым или не показываем вовсе. Уже принятый на экран текст не переписываем — только дополняем.

## Правила отображения

- **Максимум 2 строки**, скользящее окно; старое уезжает вверх.
- **~42 символа в строке** (для иврита ориентир ниже, ~40) — иначе глаз не успевает.
- **Скорость чтения ~17 знаков/сек** — если перевод длиннее произнесённого, лучше показать полностью и дать доехать, чем резать.
- **Перенос строки по смысловым границам**, не по ширине контейнера.
- **Минимальное время на экране ~1 с** даже для коротких реплик — иначе мигает.
- **Атрибуция говорящего** обязательна с момента появления третьего участника (группы), в 1:1 — опционально.

## Два языка на экране

Дизайн-решение для SpeakEasy: **основной — то, что человек понимает** (перевод), оригинал — вторичный, приглушённый, меньшим кеглем. Не наоборот. Оригинал остаётся доступен всегда (принцип «Show original» из концепции — он же страховка доверия: ошибка перевода должна быть проверяема).

Оригинал полезен даже тому, кто языка не знает: видно, что система *слышит* (это снимает тревогу «меня вообще понимают?»).

## Иврит: RTL и конкретные грабли

- `dir` выставлять **поэлементно по языку строки**, не глобально на страницу. Русский блок — `ltr`, ивритский — `rtl`.
- Смешанный контент (иврит + латиница + цифры) — `dir="auto"` / `unicode-bidi: plaintext` на контейнере строки, иначе bidi-алгоритм выкинет пунктуацию не на тот край. Классический баг: точка/вопросительный знак уезжает в начало строки.
- Иврит пишется **без огласовок (никуд)** — это проблема не для чтения субтитров, а для TTS (см. [05-providers.md](05-providers.md)); в субтитрах текст оставляем как есть, без диакритики.
- Шрифт должен иметь нормальное ивритское начертание; системные стеки на iOS/Android справляются, но проверить на реальном устройстве обязательно.
- Выравнивание блока: ивритский текст прижимается вправо, русский — влево. Центрирование обоих скрывает проблему, но выглядит неряшливо при длинных строках.

## Что из этого попадает в скелет

Минимум для этапа 0 (проверяется на веб-клиенте): 2 строки, скользящее окно, стабилизация частичных гипотез, `dir` по языку, перевод крупно / оригинал мелко. Остальное — по мере появления реальных звонков.
